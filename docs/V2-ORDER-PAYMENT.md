# 🆕 เวอร์ชัน 2 — รับออเดอร์ในแชท + ยืนยันการชำระเงิน + ทะเบียนลูกค้า (CRM)

ไฟล์: `workflow/imjai-line-ai-agent-v2.json`

นี่คือเวอร์ชันที่ต่อยอดจากไฟล์ workflow ที่ใช้งานจริงอยู่ตอนนี้ (Gemini + Google Sheets: `Menu_FAQ` / `Orders` / `Chat_Log`)
เพิ่ม 3 เรื่องที่ขอมา — **(1)** ให้ AI รับออเดอร์ในแชทได้เลย **(2)** เก็บข้อมูลลูกค้าแยกเป็นทะเบียนลูกค้าต่างหาก
**(3)** ระบบยืนยันการชำระเงินหลังลูกค้าโอนเงินจริง — พร้อมแก้บั๊กที่เจอ

## 🐞 บั๊กที่พบและแก้แล้วในไฟล์เดิม

| บั๊ก | ผลกระทบ | วิธีแก้ |
|---|---|---|
| **ข้อความมี `\n` โผล่เป็นตัวอักษรจริง** (ตามภาพหน้าจอที่ส่งมา) | ลูกค้าเห็น `\n` แทนการขึ้นบรรทัดใหม่ ดูไม่เป็นมืออาชีพ | เพิ่มการ normalize ใน `Format Agent Output` + สั่งในระบบ prompt ห้ามพิมพ์ `\n` เป็นตัวอักษร |
| **LINE Reply ส่ง Authorization header ซ้ำ 2 อัน** — ทั้งจาก credential และพิมพ์ตรงในไฟล์ | เสี่ยงให้ LINE API ตอบ 401 แล้วลูกค้าไม่ได้รับข้อความตอบกลับเลย (น่าจะเป็นสาเหตุหลักของ "ตอบผิดพลาด" ที่เจอบ่อย) | ลบ header ที่พิมพ์ตรงออก เหลือแค่ credential ใส่ให้ |
| **system prompt สั่งให้เรียก `create_ticket` แต่ไม่มี tool นี้อยู่จริงในไฟล์** | ทุกครั้งที่ลูกค้าร้องเรียน/ขอคืนเงิน AI จะพยายามเรียก tool ที่ไม่มี → error/หลอน | สร้าง tool `create_ticket` จริง เขียนลงชีตใหม่ `Tickets` |
| **โมเดล `models/gemini-3.5-flash-lite` ไม่มีอยู่จริง** | เรียก Gemini API แล้วน่าจะ error หรือ fallback แปลก ๆ | แก้เป็น `models/gemini-2.5-flash` (ปรับได้ตาม budget ที่ node `Google Gemini Chat Model`) |
| **Discord Webhook URL และ LINE Channel Access Token ฝังเป็นข้อความล้วนในไฟล์** | ใครก็ตามที่เห็นไฟล์นี้ (เช่นใน git) ส่งข้อความปลอมเข้า Discord หรือ LINE แทนร้านได้ทันที | ย้ายไปเก็บใน node `⚙️ Config` และ**ลบค่าจริงออกจากไฟล์** — ดูหัวข้อความปลอดภัยด้านล่าง **ต้องทำตามด่วน** |

> ⚠️ **สำคัญมาก:** ไฟล์ต้นฉบับที่ส่งมามี Discord Webhook URL และ LINE Channel Access Token ตัวจริงฝังอยู่
> ผมลบออกจากไฟล์ที่ commit ให้แล้ว แต่ **ค่าที่หลุดมานั้นควรถือว่ารั่วไหลแล้ว** แนะนำให้ไป:
> 1. LINE Developers Console → Issue token ใหม่ (revoke ตัวเก่า)
> 2. Discord → ลบ Webhook เดิม สร้างใหม่
> แล้วเอาค่าใหม่ไปตั้งใน credential/`⚙️ Config` แทน

## 🗺️ ภาพรวมสิ่งที่เพิ่ม

```
ลูกค้าคุยกับ AI → สั่งอาหาร → AI สรุปออเดอร์ให้ยืนยัน → ลูกค้ายืนยัน
   → create_order (บันทึกลง Orders, payment_status=unpaid) + save_customer_info (บันทึกลง Customers)
   → แจ้ง Discord ทีมงาน "มีออเดอร์ใหม่" พร้อมลิงก์ "ยืนยันว่าชำระเงินแล้ว"
   → ⏸ ระบบรอสูงสุด 48 ชม.
        ├─ ทีมงานเช็คสลิป/เงินเข้าจริง แล้วกดยืนยันจากหน้าเว็บ (กันบอท/Discord prefetch กดเอง)
        │     → อัปเดต Orders: payment_status=paid, status=ชำระเงินแล้ว-กำลังเตรียม
        │     → Push LINE แจ้งลูกค้าอัตโนมัติว่าได้รับเงินแล้ว
        └─ ไม่มีใครกดภายใน 48 ชม. → Discord เตือนซ้ำ ไม่มีการอัปเดตสถานะใด ๆ (fail-safe)
```

**AI ไม่มีสิทธิ์สั่ง "ชำระเงินแล้ว" เองเด็ดขาด** — พิสูจน์เชิงโครงสร้างด้วย `tests/guard-payment.js`
(เหมือนที่ `imjai-line-ai-agent-full.json` มี `tests/guard-approval.js` พิสูจน์เรื่องคืนเงิน/ยกเลิกออเดอร์อยู่แล้ว)

## Google Sheet ต้องมี 5 แท็บ (ในไฟล์ `IM JAI SHEET` เดิม)

| แท็บ | สถานะ | คอลัมน์ |
|---|---|---|
| `Menu_FAQ` | มีอยู่แล้ว ไม่ต้องแก้ | type, topic, detail, status |
| `Orders` | **ต้องเพิ่มคอลัมน์** | order_id, created_at, line_user_id, customer_name, customer_phone, items, order_type, delivery_address, total_amount, status, payment_status, eta, paid_at, confirmed_by, note |
| `Chat_Log` | **ต้องเพิ่มคอลัมน์** | timestamp, line_user_id, user_message, reply_text, intent, sentiment, need_admin, reason, **order_id** ← คอลัมน์ใหม่ |
| `Customers` | **สร้างแท็บใหม่** | line_user_id, customer_name, phone, address, last_contact_at |
| `Tickets` | **สร้างแท็บใหม่** | ticket_id, created_at, line_user_id, order_id, category, action_requested, is_high_risk, message, status |

**วิธีเร็วที่สุด:** ใช้ `data/v2/ImJai_Database_v2.xlsx` — ไฟล์เดียวมีครบทั้ง 5 แท็บ + แท็บ "อ่านก่อนใช้" อธิบายแต่ละคอลัมน์
ลากขึ้น Google Drive → คลิกขวา → **Open with → Google Sheets** → **File → Save as Google Sheets** ได้ครบทุกแท็บในคลิกเดียว

หรือถ้าอยากทำเอง มีไฟล์ CSV แยกทีละแท็บให้ในโฟลเดอร์ `data/v2/` เช่นกัน — import ทีละแท็บผ่าน **File → Import → Upload → Replace current sheet**
(`Menu_FAQ.csv` แปลงจาก `data/Products.csv` + `data/KnowledgeBase.csv` เดิมให้แล้ว)

หลังสร้างแท็บ `Customers` และ `Tickets` เสร็จ ให้เปิด node **`Save Customer Tool`** และ **`Create Ticket Tool`** ใน n8n
แล้วเลือกแท็บจาก dropdown `sheetName` ใหม่อีกครั้ง (ไฟล์ตั้ง gid ชั่วคราวไว้ n8n จะขึ้นเตือนให้เลือกใหม่เอง)

## ตั้งค่า node `⚙️ Config` (จุดเดียวจบ ไม่ต้องไปแก้หลายที่)

| ตัวแปร | ใส่อะไร |
|---|---|
| `DISCORD_WEBHOOK_URL` | Webhook ใหม่ที่สร้างแทนตัวที่หลุดไป |
| `PUBLIC_BASE_URL` | URL สาธารณะของ n8n คุณ (ไม่ต้องมี `/` ปิดท้าย) ใช้สร้างลิงก์ยืนยันการชำระเงิน |
| `APPROVAL_SECRET` | ตั้งรหัสสุ่มของตัวเอง (เช่น `imjai-Xq82!kd93`) ใช้เซ็นลิงก์ยืนยันกันคนอื่นปลอมลิงก์ |
| `QR_IMAGE_URL` | เว้นว่างไว้ก่อนได้ตามที่แจ้งว่าจะส่ง QR มาทีหลัง — ใส่ทีหลังได้โดยไม่ต้องแก้ node อื่น |
| `PROMPTPAY_NAME` / `STORE_NAME` | ใช้โชว์ในข้อความ/หน้ายืนยัน ปรับได้ตามต้องการ |

`Google Sheets`, `LINE`, `Google Gemini` credential ใช้ตัวเดิมที่ผูกไว้อยู่แล้ว ไม่ต้องสร้างใหม่
(เว้นแต่จะไป revoke LINE token ตามคำแนะนำด้านบน ก็แค่แก้ค่าใน credential เดิม ไม่ต้องสร้าง credential ใหม่)

### ตั้งแจ้งเตือนเมื่อระบบล่ม (Error Workflow)

ไฟล์นี้มี node `Error Trigger` → `Build System Error Alert` → `Discord — แจ้งระบบพัง` ให้แล้ว
แต่ n8n ต้องตั้งค่าเพิ่ม 2 จุดถึงจะทำงาน:

1. เปิด node **`Build System Error Alert`** → แก้บรรทัด `WEBHOOK = 'PASTE_YOUR_DISCORD_WEBHOOK_URL_HERE'` เป็น URL จริง
   (ต้องแก้ตรงนี้ **แยกจาก** `⚙️ Config` เพราะ error workflow รันคนละ execution จากตัวที่ล่ม เลยอ้างอิง node อื่นข้ามไม่ได้)
2. หน้า workflow → **⋯ → Settings → Error Workflow → เลือก workflow นี้เอง**

ตั้งแล้วถ้า node ไหนพังกลางทาง Discord จะเด้งบอกทันทีว่าพังตรงไหน แทนที่ลูกค้าจะเงียบไปเฉย ๆ โดยไม่มีใครรู้

## ทำไมไม่ให้ AI ยืนยันการชำระเงินเอง

เพราะ AI **ไม่มีทางรู้ได้จริงว่าเงินเข้าบัญชีร้านแล้วหรือยัง** (ไม่ได้ต่อ payment gateway) — ถ้าปล่อยให้ AI พูดว่า "ชำระแล้ว"
จากที่ลูกค้าพิมพ์บอกเฉย ๆ จะเปิดช่องให้มิจฉาชีพหลอกว่าจ่ายแล้วทั้งที่ยังไม่จ่ายจริง ระบบนี้เลยออกแบบให้:

1. AI สร้างออเดอร์ได้ (`create_order`) แต่ตั้ง `payment_status=unpaid` ตายตัว แก้เป็น `paid` ไม่ได้เอง
2. มีแค่ **คนกดยืนยันจากหน้าเว็บที่มีลิงก์เซ็นด้วย `APPROVAL_SECRET`** เท่านั้นที่ทำให้ `payment_status` เป็น `paid`
3. หน้ายืนยันดึงข้อมูลออเดอร์สดจากชีตมาโชว์ให้ทีมงานเห็นของจริงก่อนกด ไม่ใช่แค่เชื่อข้อความใน Discord
4. ลิงก์ใน Discord ไม่ได้ชี้ตรงไปสั่งงาน (กัน Discord bot prefetch ลิงก์แล้วกดยืนยันเอง) ต้องเปิดหน้าเว็บแล้วกดปุ่มจริงเท่านั้น

รันตรวจสอบโครงสร้างนี้ได้ด้วย `node tests/guard-payment.js`

## การแนะนำสินค้า (upsell) ที่ปรับปรุง

- ลูกค้าถามหาเมนูกว้าง ๆ → AI ถาม 1 คำถามก่อน (งบ/หวานหรือคาว/เผ็ดได้ไหม) แล้วเสนอ 2–3 ตัวเลือกพร้อมราคาจริงจาก `get_product_info`
- สั่งของคาวแล้ว → เสนอเครื่องดื่ม/ของหวาน 1 อย่างเสมอ ไม่ยัดเยียดซ้ำถ้าลูกค้าปฏิเสธ
- แจ้งโปรโมชันที่ active อยู่และเข้ากับสิ่งที่ลูกค้ากำลังสั่ง (อ่านจากคอลัมน์ `detail` ใน `Menu_FAQ` เหมือนเดิม)

| `ของถึงไหนแล้ว ORD-...` | บอกสถานะ + สถานะการชำระเงินที่แท้จริงจากชีต ไม่มั่ว |

## ที่ยังไม่ได้ทำ (ทำต่อได้ในอนาคต)

- **payment gateway อัตโนมัติ** (พร้อมเพย์/ธนาคาร) — ตอนนี้เป็นแบบแอดมินกดยืนยันเอง ถ้าอยากเชื่อมอัตโนมัติทีหลัง
  แค่เพิ่ม Webhook รับ callback จาก gateway แล้วยิงเข้า resume URL เดียวกับที่ปุ่มยืนยันใช้อยู่ตอนนี้ได้เลย ไม่ต้องออกแบบใหม่
- **รูป QR จริง** — ใส่ลิงก์รูปที่ `QR_IMAGE_URL` ใน `⚙️ Config` ได้ทันทีที่มี ไม่ต้องแก้ node อื่น
