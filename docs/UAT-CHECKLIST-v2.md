# ✅ เช็กลิสต์ทดสอบก่อนใช้งานจริง — v2

ผมทดสอบให้ได้แค่ "โครงสร้าง/ตรรกะ" ของไฟล์ workflow เท่านั้น (รันเป็นสคริปต์ตรวจ JSON ล้วน ๆ)
เพราะไม่มีสิทธิ์เข้าถึง n8n instance, Google Sheet, LINE OA, Discord หรือ Gemini API ตัวจริงของคุณ
— สิ่งที่ต่อไปนี้ **ต้องลองพิมพ์ในแชท LINE จริงด้วยตัวเอง** ถึงจะยืนยันได้ว่าใช้งานได้จริง 100%

## สิ่งที่ผมทดสอบให้แล้ว (ผ่านหมด ✅)

```bash
node tests/guard-payment.js     # ✅ ยืนยัน: ไม่มีเส้นทางใดข้ามการอนุมัติจ่ายเงินได้ AI สั่ง paid เองไม่ได้
node tests/guard-approval.js    # ✅ ยืนยัน: เรื่องคืนเงิน/ยกเลิก/ส่วนลด ต้องผ่านอนุมัติเสมอ
node tests/run-tests.js         # ✅ 18/18 เคส logic ผ่าน (เวอร์ชัน full)
node tests/run-tests-lite.js    # ✅ 25/25 เคส logic ผ่าน (เวอร์ชัน lite)
```

รวมถึงตรวจว่า JSON ไม่มี node หรือ connection ที่อ้างถึงกันไม่เจอ (dangling reference) และไม่มี secret จริงหลงเหลือในไฟล์

**สิ่งเหล่านี้พิสูจน์แค่ว่า "ผังงานเดินถูกทาง" — ไม่ได้พิสูจน์ว่า AI ตอบเก่ง, Google Sheets เขียนได้จริง,
Discord/LINE ส่งถึงจริง หรือ Gemini API ทำงานได้ ต้องเทสจริงตามด้านล่างนี้**

## 1. เทสพื้นฐาน — AI ต้องเรียก tool ได้ ไม่ error

| พิมพ์ในแชท | ต้องได้ผลแบบไหน | เช็คตรงไหนว่าจริง |
|---|---|---|
| `ร้านเปิดกี่โมง` | ตอบเวลาทำการทันที ไม่มี `\n` โผล่เป็นตัวอักษร | อ่านข้อความบน LINE เอง |
| `ลาเต้ราคาเท่าไหร่` | ตอบ 70 บาท | เทียบกับราคาที่ตั้งในชีต `Menu_FAQ` |
| `ต้มยำกุ้งมีไหม` | บอกว่าหมดวันนี้ + เสนอเมนูใกล้เคียง | เช็คว่าแถว Menu_FAQ ตั้ง status=out_of_stock |
| เปิด n8n → แท็บ **Executions** | execution ล่าสุดต้องขึ้น ✅ ไม่ใช่ ❌ | ดูสีของ execution ในหน้า n8n |

ถ้ามีข้อความไหน execution ขึ้นสีแดง (error) → เปิดดู node ที่พัง ส่งภาพมาให้ผมดูได้เลย

## 2. เทสรับออเดอร์ในแชท (หัวใจหลักของ v2)

พิมพ์ทีละข้อความ อย่ารีบ:

1. `อยากกินอะไรสักอย่าง งบ 100 บาท` → **ต้องได้:** AI ถามกลับ 1 คำถาม (เผ็ดได้ไหม/หวานหรือคาว) แล้วเสนอ 2-3 เมนูพร้อมราคาจริง
2. `เอาข้าวผัดกะเพราหมูสับ 1 จานค่ะ` → **ต้องได้:** AI เสนอเครื่องดื่ม/ของหวานเพิ่ม 1 อย่าง (upsell)
3. ตอบปฏิเสธ เช่น `ไม่เอาค่ะ` → **ต้องได้:** AI ไม่ถามซ้ำ ไปต่อขั้นตอนถามช่องทางรับของ
4. `มารับเองค่ะ` → **ต้องได้:** AI ถามชื่อ+เบอร์โทร (ถ้ายังไม่เคยให้)
5. ให้ชื่อ+เบอร์ → **ต้องได้:** AI สรุปออเดอร์เต็ม (รายการ+ราคา+ยอดรวม+ช่องทางรับของ) แล้วถามยืนยัน
6. `ยืนยันค่ะ` → **ต้องได้:** AI แจ้งเลขที่ออเดอร์ (รูปแบบ `ORD-YYYYMMDD-XXX`) + ยอดที่ต้องจ่าย + บอกว่าจะส่ง QR ให้

**เช็คว่าจริง (สำคัญมาก อย่าเชื่อแค่คำตอบในแชท):**
- เปิด Google Sheet แท็บ `Orders` → ต้องมีแถวใหม่ที่มี order_id ตรงกับที่ AI บอก, `payment_status = unpaid`, `status = รอชำระเงิน`
- เปิดแท็บ `Customers` → ต้องมีชื่อ/เบอร์ที่เพิ่งให้ไปปรากฏ (แถวใหม่ หรืออัปเดตแถวเดิมถ้าเคยคุยมาก่อน)
- เปิด Discord → ต้องมีข้อความ **"🛎️ มีออเดอร์ใหม่"** พร้อมลิงก์ **"ยืนยันว่าชำระเงินแล้ว"**

## 3. เทสระบบยืนยันการชำระเงิน (ต้องเทสให้ครบ ห้ามข้าม)

1. กดลิงก์ **"ยืนยันว่าชำระเงินแล้ว"** ใน Discord (จากข้อ 2)
2. **ต้องได้:** เปิดหน้าเว็บสีขาว/ม่วงอ่อน โชว์ชื่อลูกค้า/รายการ/ยอดเงินที่ **ตรงกับในชีตจริง** (ไม่ใช่แค่ข้อความ Discord)
3. พิมพ์ชื่อผู้ยืนยัน (เช่น "พนักงานเก็บเงิน") แล้วกดปุ่ม **"ยืนยันว่าชำระเงินแล้ว"**
4. **ต้องได้:** ปุ่มเปลี่ยนเป็น "✅ ยืนยันเรียบร้อย"
5. กลับไปดูแชท LINE ของลูกค้า(เทส) → **ต้องได้:** มีข้อความ push ใหม่แจ้งว่าได้รับเงินแล้ว ส่งมาเอง **โดยไม่ต้องพิมพ์อะไรเพิ่ม**
6. เปิดชีต `Orders` อีกครั้ง → แถวเดิมต้อง `payment_status = paid`, `status = ชำระเงินแล้ว - กำลังเตรียม`, มี `paid_at` และ `confirmed_by` เป็นชื่อที่พิมพ์ไปข้อ 3

**เทสกรณีปลอมลิงก์ (เช็คความปลอดภัย):** ลองแก้ query string ใน URL มั่ว ๆ (เช่นเปลี่ยน token) แล้วเปิดดู
→ **ต้องได้:** หน้า "🚫 ลิงก์ไม่ถูกต้องหรือหมดอายุ" ไม่ใช่หน้ายืนยันจริง

**เทสถามสถานะออเดอร์หลังชำระ:** พิมพ์ `ออเดอร์ [เลขที่] ถึงไหนแล้ว` → ต้องตอบว่าชำระเงินแล้วจริง (อ่านจากชีตไม่ใช่จำจากบทสนทนาเก่า)

## 4. เทสกรณีต้องส่งต่อแอดมิน (ห้าม AI ตัดสินใจเอง)

| พิมพ์ | ต้องได้ |
|---|---|
| `ขอเงินคืนค่ะ อาหารไม่อร่อย` | AI ขอโทษ + บอกว่าส่งเรื่องให้ทีมงานแล้ว **ไม่พูดว่า "คืนเงินให้แล้ว"** |
| — | เช็คชีต `Tickets` ต้องมีแถวใหม่ category=refund |
| — | เช็ค Discord ต้องมีข้อความแจ้ง "มีลูกค้าต้องการแอดมิน" |
| `เจอเส้นผมในอาหาร` | ห้ามมีอีโมจิในคำตอบ + is_high_risk=TRUE ในชีต Tickets |
| `ขอคุยกับแอดมิน` | Discord เด้งทันที |

## 5. เทสความเสถียร (ทำให้ "ไม่มีสะดุด" ในทางปฏิบัติ)

ไม่มี AI ตัวไหนตอบถูก 100% ทุกครั้งแบบรับประกันได้ (ธรรมชาติของ LLM) แต่ลดโอกาสพลาดและจับได้เร็วขึ้นได้ด้วยขั้นตอนนี้:

1. **ตั้ง Error Workflow** — ไป n8n → เปิด workflow v2 → **⋯ → Settings → Error Workflow → เลือก workflow นี้เอง**
   (ผมเพิ่ม node `Error Trigger` + `Build System Error Alert` ให้แล้วในไฟล์ล่าสุด แต่ต้อง**ใส่ Discord Webhook URL ในโค้ดของ node `Build System Error Alert` เองอีกที** เพราะ error workflow รันคนละ execution จาก `⚙️ Config` เดิมอ้างอิงไม่ถึง)
   → ตั้งแล้วถ้า workflow ล่มกลางทาง Discord จะเด้งแจ้งทันทีว่า node ไหนพัง แทนที่ลูกค้าจะเงียบไปเฉย ๆ โดยไม่มีใครรู้
2. **ทดสอบกับตัวเองก่อน 2-3 วัน** ก่อนปล่อยลูกค้าจริงทั้งหมด — ลองคุยหลากหลายสถานการณ์ตามเช็กลิสต์นี้
3. **เปิดชีต `Chat_Log` ดูทุกวันในสัปดาห์แรก** — หาข้อความที่ AI ตอบแปลก ๆ หรือ `need_admin=TRUE` บ่อยผิดปกติ
   แล้วเอาคำถามที่ตอบไม่ดีไปเพิ่มเป็นข้อมูลใน `Menu_FAQ` หรือปรับ system prompt เพิ่ม
4. **เช็คโควต้า/บิล Gemini API** อย่าให้ over quota เพราะจะทำให้ AI Agent error ทุกข้อความจนกว่าจะรีเซ็ต
5. ถ้าเจอเคสไหนตอบผิดซ้ำ ๆ ส่งข้อความจริงที่ลูกค้าพิมพ์มาให้ผมดู จะช่วยปรับ system prompt ให้ตรงจุดขึ้นได้

## สรุป

ผมช่วยพิสูจน์เชิงโครงสร้าง (ผังงานถูกทาง, security guard ผ่านหมด) และแก้บั๊กที่เจอจากภาพหน้าจอได้
แต่ **การยืนยันว่า "ใช้งานได้จริง 100%" ต้องเป็นคุณเดินเทสตามเช็กลิสต์ข้อ 1-4 ข้างบนด้วยตัวเอง**
เพราะเป็นระบบที่ต่อกับ LINE OA / Google Sheet / Discord / Gemini ของคุณโดยตรง ผมไม่มีทางเข้าถึงได้จากตรงนี้

ทดสอบแล้วติดตรงไหน ส่งภาพ execution ที่ error หรือคำตอบที่ AI ตอบแปลกมาได้เลย จะไล่แก้ให้ทีละจุด
